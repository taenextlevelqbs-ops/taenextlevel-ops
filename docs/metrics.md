# Metric definitions and boundaries

| Metric                | Real source                                  | Meaning / limitations                                                                                                                                                                    |
| --------------------- | -------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Unique visitors       | GA4 `activeUsers`                            | Unique active users as defined by GA4 for one property. Consent, blockers, bots and provider processing affect coverage.                                                                 |
| Portfolio audience    | Sum of connected sites' active users         | Not deduplicated across properties. Coverage is visible. Unknown sites are not counted as zero.                                                                                          |
| Page views            | GA4 `screenPageViews`                        | Property totals. Daily series is zero-filled only after a successful provider report.                                                                                                    |
| Live visitors         | GA4 realtime `activeUsers`                   | Last 30 minutes, not instantaneous presence. Unavailable if realtime permission fails.                                                                                                   |
| Windows               | UTC trailing 1, 7, 30, 365 calendar days     | Current partial day is included; current windows end tomorrow at 00:00 UTC. Previous windows have equal length.                                                                          |
| Growth                | `(current - previous) / previous`            | Unavailable when previous is zero or unknown. Only measured traffic totals are compared.                                                                                                 |
| Top pages             | GA4 `pagePath` + `screenPageViews`           | Six most viewed paths; query strings are not requested.                                                                                                                                  |
| Sources               | GA4 `sessionSourceMedium` + `sessions`       | Six sources by sessions, which differs from active users.                                                                                                                                |
| Devices               | GA4 `deviceCategory` + `activeUsers`         | Provider-defined desktop/mobile/tablet categories. Users can overlap device categories.                                                                                                  |
| Leads / registrations | Exact-count HEAD to a Supabase table/view    | Created in the window, not visitors or conversion rates. Default timestamp is `created_at`; configurable. No records or PHI are downloaded.                                              |
| Bookings              | Calendly active scheduled events             | Events starting in the window; not date of booking creation, attendee count, or revenue. Pagination is traversed; capped results are unavailable.                                        |
| Payments              | Stripe captured succeeded charges            | Successful captured charges created in the window. Net amount subtracts refunds currently recorded. Currencies stay separate; amounts are minor units, without guessed currency scaling. |
| Uptime                | Dedicated persistent scheduled HTTPS samples | Percentage of known successful probes. Unknown/proxy/network failures are not asserted as downtime. Shows sample counts, unknown counts, truncation and last measured timestamp.         |
| Response time         | Scheduled probe                              | Headers received for GET including followed redirects; not full page rendering.                                                                                                          |
| Vercel deployments    | Vercel API                                   | Latest eight deployments in the period. `ERROR` is never presented as `READY`. No synthetic deployment status.                                                                           |
| GitHub activity       | GitHub commits and Actions APIs              | Latest eight commits in the period, latest five workflow runs, plus provider exact count of failed workflows in the period. Empty/unavailable repositories remain unavailable.           |
| Application errors    | Sentry received error events                 | Error-event volume, not all application logs or all unique issues. Requires an installed project SDK.                                                                                    |

Read failures are sanitized: no raw provider exception, token, or response body reaches the browser. Service adapters are tested against explicit provider fixtures. Live provider account validation remains distinct from those tests.

Historical traffic comes from GA4-retained reports. Monitoring history begins when scheduled probes are configured. Availability is sampled, not an SLA guarantee. Uptime result retrieval is capped at 10,000 rows per period and shows truncation. New registry entries are persistent only when the dedicated database works; saving fails honestly when it does not.

Daily aggregate analytics snapshots are retained in the dedicated `command_daily_metrics` table. They use the previous complete UTC day and preserve unavailable fields as null with source/reason metadata. These are sampled provider readings, not customer records. GA4 processing delays may produce later revisions; daily unique users are not summed into monthly unique users. Production sign-in uses the dedicated Supabase Auth account, exact owner UUID, verified email, and shared database throttle.
